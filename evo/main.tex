\section{configuration}

Use the network configuration described in \texttt{Security Analysis of Ripple Consensus}, with 7 nodes and node 3 as the byzantine node.

All tests set a maximum ledger sequence of 15. Byzantine node (3) mutates messages in $3 \leq \text{seq} \leq 10$.

specification checking:
\begin{enumerate}
    \item failed agreement: true if all node didn't agree on same ledger hashes in each ledger sequence
    \item failed final agreement: true if ledger hashes are collected for all nodes in the last ledger sequence and these hashes are identical
\end{enumerate}

\textit{validation time}s are the time intervals between two consecutive statuschange messages with new-event = closing ledger. 

\textit{proposset number} is the total number of TMProposeSet messages sent by a node in a test, averaged.

byzantine nodes are excluded from violaiton checking.
